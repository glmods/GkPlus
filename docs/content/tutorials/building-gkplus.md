# Building GkPlus

This tutorial is for a **developer**: someone who is going to work on GkPlus itself.

In this tutorial we clone the repository, get its dependencies, configure it with its
CMake preset, build `d3d8.dll`, deploy it into a Steam copy of Gunlok, then change one
line of C++ and watch our own words appear on Gunlok's main menu.

The first configure builds every dependency from source and takes a long time. Everything
after that is a fast edit-build-run loop, and that loop is what this tutorial is really
for.

## Before we start

GkPlus builds a 32-bit Windows DLL with clang-cl, and the build refuses to configure at
all on anything else. We need all of the following present before we begin:

- **Windows 10 or 11.**
- **Git.**
- **CMake 3.24 or newer**, on `PATH`.
- **Ninja**, on `PATH`.
- **LLVM**, with `clang-cl` on `PATH`.
- **Visual Studio 2022 or newer** with the *Desktop development with C++* workload.
  `clang-cl` compiles the code but uses Microsoft's headers and 32-bit libraries to do it.
- **Python 3**, on `PATH`. Two headers in this build are generated by Python scripts, and
  CMake stops with a fatal error if it cannot find an interpreter.
- **The Vulkan SDK**, which is where `slangc` comes from. CMake looks for it on `PATH` and
  then in `C:\VulkanSDK\*\Bin`, and stops with a fatal error if it finds neither.
- **Gunlok, installed through Steam.** The deploy step finds the install through Steam's
  own registry entry.
- **About 10 GB of free disk space**, most of it for the dependency build.

Open a **PowerShell** window and check the four tools on `PATH`:

```
cmake --version
ninja --version
clang-cl --version
python --version
```

Each prints a version. If any of them says the command is not recognised, install that one
before going on.

## Step 1: clone the repository

```
git clone https://github.com/frabert/GkPlus.git
cd GkPlus
```

Git prints its usual progress and leaves you in the checkout. Everything from here on is
run from this directory, and the prompt now ends in `GkPlus`.

## Step 2: get vcpkg

GkPlus takes its dependencies from vcpkg, and the `builtin-vcpkg` preset expects a vcpkg
clone inside the checkout. It is not a submodule, so `git clone` did not bring it: we
fetch and bootstrap it ourselves.

```
git clone https://github.com/microsoft/vcpkg.git vcpkg
.\vcpkg\bootstrap-vcpkg.bat
```

The bootstrap downloads a prebuilt vcpkg and finishes with a line naming its version.
Check that the executable is there:

```
dir vcpkg\vcpkg.exe
```

Explorer or `dir` shows one file. If it is missing, run the bootstrap again; nothing else
will work without it.

## Step 3: configure

```
cmake --preset builtin-vcpkg
```

**This is the long step.** vcpkg builds ImGui, Detours, d3d8to9, QuickJS, PhysicsFS and the
Vulkan libraries from source, for the 32-bit static-md triplet, and that takes tens of
minutes on a first run. It scrolls a great deal of build output that is not ours.

When it reaches GkPlus's own configure it prints CMake status lines. Two are worth
watching for:

```
-- Slang shaders: C:/VulkanSDK/1.4.341.0/Bin/slangc.exe
```

meaning the shader compiler was found (your version number will differ), and

```
-- Build files have been written to: C:/.../GkPlus/build
```

as the last line, meaning configure succeeded. A `build` folder now exists in the checkout.

We only ever run this command again when we change the build itself; ordinary source edits
do not need it.

## Step 4: build the DLL

```
cmake --build build
```

This compiles the Slang shaders, generates two headers into the build tree, and compiles
and links the DLL. Expect a wall of warnings on the way through: a translation unit that
includes `src/Actors.h` emits about thirty `-Winvalid-offsetof` warnings, and they are
expected and harmless.

The last line is the one that matters:

```
[64/65] Linking CXX shared module Debug\d3d8.dll
```

The DLL is now at `build\Debug\d3d8.dll`. Confirm it:

```
dir build\Debug\d3d8.dll
```

Because the generator is Ninja Multi-Config and the default configuration is Debug, that
is what we just built and what we will deploy.

The warnings will bury your own diagnostics on every later build, so it is worth learning
the filter now. Run the build through it:

```
cmake --build build 2>&1 | Select-String ': (warning|error):' | Select-String -NotMatch 'invalid-offsetof'
```

Nothing has changed since the last build, so this one prints nothing at all. The build is
already up to date.

## Step 5: deploy into Gunlok

**Close Gunlok first if it is running.** Windows holds the DLL open while the game has it
loaded, and the copy fails with a permission error.

```
cmake --build build --target copy
```

It prints a line or two and finishes. The DLL is now next to `gl.exe` in the Steam
install, usually:

```
C:\Program Files (x86)\Steam\steamapps\common\Gunlok\d3d8.dll
```

## Step 6: see the build running

Start Gunlok from Steam and let it reach the main menu.

Read the **bottom-left corner**. A stock Gunlok prints `v1.3 DX8` there. Our build prints:

```
GkPlus - d3d9 (Debug)
```

That string is coming out of the DLL we just built. `d3d9` is the renderer GkPlus
resolved, and `(Debug)` is there because this is a Debug build.

Quit the game.

## Step 7: change the code

That stamp is built in `src/Font.cpp`, in a function called `VersionText()`. Open the file
and find this line, which is line 58:

```cpp
  static const std::string text = std::string("GkPlus - ") + d3d8::RendererName() IS_DEBUG_STR;
```

Change the literal `"GkPlus - "` to `"GkPlus, my build - "`, so the line reads:

```cpp
  static const std::string text = std::string("GkPlus, my build - ") + d3d8::RendererName() IS_DEBUG_STR;
```

Save the file.

## Step 8: rebuild, redeploy, and look

```
cmake --build build
cmake --build build --target copy
```

The build is much shorter this time: one file recompiles and the DLL relinks, and the
last line is again `Linking CXX shared module Debug\d3d8.dll`.

Start Gunlok from Steam and read the bottom-left corner of the main menu again:

```
GkPlus, my build - d3d9 (Debug)
```

That is the whole loop: edit, `cmake --build build`, `cmake --build build --target copy`,
launch. It is the loop nearly all work on GkPlus happens in.

Quit the game.

## Step 9: put it back

```
git checkout src/Font.cpp
cmake --build build
cmake --build build --target copy
```

The stamp is back to `GkPlus - d3d9 (Debug)`, and the checkout is clean:

```
git status
```

prints `nothing to commit, working tree clean`.

## What we have done

We built a 32-bit `d3d8.dll` from source with clang-cl, Ninja and vcpkg, deployed it into
a Steam copy of Gunlok with the `copy` target, and put a string of our own on the game's
main menu, proving the DLL in the game folder is the one we just compiled.

You now have a working checkout, a configured build tree, and an edit-build-run loop that
takes under a minute.
